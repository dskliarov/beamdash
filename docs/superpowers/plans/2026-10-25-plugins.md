# Plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Application plugins for beamdash. Each plugin is installed from a Mix-style dependency (Hex, Git or a local path), managed in Settings → Plugins, and shown in a Plugins menu when its app runs on the attached node at a supported version. The first plugin is riak_core.

Supported applications and their versions are declared in the plugin's own `mix.exs` `deps`. They are `runtime: false` deps, read as data; for example `{:riak_core, "~> 0.10", hex: :riak_core_lite, runtime: false}`.

**Architecture:**
- `Beamdash.Plugins.Spec` parses the dependency text without evaluating it.
- `Beamdash.Plugins.Fetch` gets only the plugin's own source.
- `Beamdash.Plugins.Build` scans, compiles in-process into a private ebin, checks, then loads or purges.
- `Beamdash.Plugins`, a GenServer, keeps `plugins.json`, runs installs in a Task, reloads at startup, and tracks which plugins are active from the node's running apps.
- The plugin API is `Beamdash.Plugin` and `Beamdash.Plugin.Page`.
- The UI is the Settings section, a Plugins nav menu, and `PluginLive`, which embeds a plugin page with `live_render`.
- The riak_core plugin is a separate Mix project in `../beamdash-riak-core-plugin`.

**Tech Stack:** Elixir 1.15+ (dev machine has 1.20 and OTP 29), Phoenix LiveView 1.2.12, plain CSS/JS, `git` and `mix` (Hex) as OS processes.

Spec: `docs/superpowers/specs/2026-10-24-plugins-design.md` (each task brief names the sections it needs).

## Global Constraints

- No commits, pushes or publishing in either repo. The beamdash working tree holds the user's uncommitted rename and earlier features; leave everything uncommitted. The plugin repo is created with `git init` and is not committed.
- The dependency text is **never evaluated**. Only `Code.string_to_quoted/1` and checks on literals are used. The same rule applies to a plugin's `mix.exs`, which is read as data and never evaluated.
- **Deletion guard:** beamdash only ever deletes paths inside `<plugins dir>/`, after `Path.expand` and resolving symlinks, and never the plugins dir itself. A path plugin's source folder is never deleted.
- **Name clashes:** no plugin module may share a name with a module beamdash, OTP, deps or another plugin already has loaded or on the code path. This is checked by scanning the sources **before** compiling.
- A broken plugin never stops beamdash from starting, never crashes `Beamdash.Plugins`, and never sets the connection bar's error.
- Tests never touch the real plugins dir. `test/test_helper.exs` sets `:plugins_dir` to a temp dir. Tests use no network: Git uses local repos via `:plugins_allow_local_git`, and Hex goes through the `:plugins_hex_cmd` seam.
- Limits: fetch timeout 120 s; plugin `app` matches `^[a-z][a-z0-9_]{0,63}$`; page slug matches `^[a-z][a-z0-9_-]{0,31}$`; active-set refresh every 10 s.
- Follow existing patterns:
  - `Beamdash.LastConnection` and `Beamdash.Settings` for files under the user config dir, written via tmp then rename;
  - `Beamdash.Logs` for a GenServer with injectable seams;
  - `BeamdashWeb.SettingsLive` cards for the UI;
  - `test/beamdash/logs_live_test.exs` for testing LiveViews by calling callbacks directly (no `lazy_html`).
- Before reading code for a question, run `graphify query "<question>"` (on PATH). Run `graphify update .` after the last beamdash task.
- Before reporting, run `mix format` and `mix compile --warnings-as-errors`. Run the full `mix test` once at the end of each task (317 pass now).

### Task 1: `Beamdash.Plugins.Spec`: parse and validate the dependency text

**Files:**
- Create: `lib/beamdash/plugins/spec.ex`
- Test: `test/beamdash/plugins_spec_test.exs` (`async: true`)

Spec sections: "The dependency field".

**Interfaces (Produces):**
- `Spec.parse(text :: String.t()) :: {:ok, spec} | {:error, message :: String.t()}`, where
  ```elixir
  spec = %{app: atom, source: :hex | :git | :path,
           requirement: String.t() | nil,            # hex only
           package: String.t(),                      # hex: hex: name or app
           url: String.t() | nil, ref: {:tag | :branch | :ref, String.t()} | nil,  # git only
           path: String.t() | nil}                   # path only, expanded
  ```
- `Spec.to_string(spec) :: String.t()` writes the term back in Mix syntax with `inspect/2`, e.g. `{:riak_core_plugin, git: "https://…", tag: "0.0.1"}`. `parse(to_string(spec))` returns the same spec.
- `Spec.allow_local_git?()` reads `Application.get_env(:beamdash, :plugins_allow_local_git, false)`. When it is true, a `git:` value may be a local path or `file://` URL (tests only).

**Rules:**
- **Parsing:** use `Code.string_to_quoted(text, existing_atoms_only: false)`, then walk the AST and accept only literals:
  - atoms;
  - binaries;
  - 2- and 3-element tuples (the 2-tuple AST is a plain tuple, the 3-tuple is `{:{}, _, [...]}`);
  - keyword lists of atom keys and binary or atom values.

  Anything else is refused with "only literal values are allowed", including calls such as `System.halt()`, variables, sigils, interpolation, `@attr` and `__MODULE__`.
- **`app`:** an atom matching `^[a-z][a-z0-9_]{0,63}$`.
- **Accepted shapes:** `{app, "req"}` is Hex; `{app, opts}` and `{app, "req", opts}` take their source from `opts`.
- **Sources:** exactly one of `git:`, `github:`, `path:` or `hex:`; with no source key but a requirement, the source is Hex.
  - `github: "owner/repo"` is the Git URL `https://github.com/owner/repo.git`.
  - Git takes at most one of `tag:`, `branch:` or `ref:`.
  - A Git `url` must match `^(https://|ssh://|git@[^:]+:)`, unless `allow_local_git?` is set.
  - `hex:` needs a requirement.
  - `path:` is expanded with `Path.expand/1`.
- **Requirement:** validated with `Version.parse_requirement/1`.
- **Unknown or unsupported keys:** refused, naming the key: `override`, `only`, `runtime`, `compile`, `manager`, `app`, `sparse`, `submodules`, `organization`, `repo`, `env`, `targets`, and any other.
- **Hints:**
  - Text that fails to parse but contains a number pattern like `, 0.0.1}` gets: `write the version as a string, as in mix.exs: {:riak_core_plugin, "0.0.1"}`. Use the actual app name if a leading `{:name` can be found, and also when the parser fails on `0.0.1`.
  - An unquoted URL, `git: https://…`, gets: `put the URL in quotes: git: "https://…"`.
  - Missing braces get: `use mix.exs dependency syntax, e.g. {:my_plugin, "~> 0.1"}`.

### Task 3: `Beamdash.Plugins.Fetch` and `Beamdash.Plugins.Build`

**Files:**
- Create: `lib/beamdash/plugins/fetch.ex`, `lib/beamdash/plugins/build.ex`
- Test: `test/beamdash/plugins_build_test.exs` (`async: false`), using the fixture from Task 2 plus small inline broken plugins written to tmp dirs.

Spec sections: "Install" steps 2–7, "Storage", "Rebuild", Global Constraints (name clashes, never evaluated).

**Consumes:** `Spec` (Task 1), `Beamdash.Plugin` (Task 2).

**Interfaces (Produces):**
- `Fetch.fetch(spec, dest_dir) :: {:ok, %{src: dir, resolved: String.t()}} | {:error, message}`.
  - **Git:** clone into `dest_dir/src`. With a tag or branch, use `git clone --depth 1 --branch X url src`. With a ref, use a full clone, then `git -C src checkout ref`. Run it with `System.cmd("git", args, stderr_to_stdout: true, env: [{"GIT_TERMINAL_PROMPT", "0"}])` inside a `Task` with a 120 s `Task.yield || Task.shutdown(:brutal_kill)`. A timeout gives `"git timed out after 120 s"`. `resolved` comes from `git -C src rev-parse HEAD`.
  - **Hex:** the command runner is `Application.get_env(:beamdash, :plugins_hex_cmd, &Fetch.default_hex_cmd/1)`. It receives an arg list and returns `{output, status}`. Steps:
    - `["hex.info", package]` gives the output; parse the versions listed under `Recent releases:` (or `Releases:`), one per line in the form `  0.11.1 (2026-06-12)`, to find the highest version satisfying the requirement. Recent releases may not include old ones; if none of the listed versions matches, the error says the matching version may be older than those Hex listed, and suggests an exact version. If none satisfies it, return a clear error.
    - `["hex.package", "fetch", package, version, "--unpack", "--output", dest/src]`.
    - `resolved` is the version.
    - `default_hex_cmd/1` runs `System.cmd(System.find_executable("mix"), args, stderr_to_stdout: true, env: [{"MIX_ENV","prod"}])`, with the same 120 s guard. `mix` not found gives `"mix not found on PATH (needed for Hex plugins)"`.
  - **Path:** check that the dir exists and contains `mix.exs`. Return `%{src: path, resolved: path}` and copy nothing.
- `Build.read_project(src) :: {:ok, %{app: atom, supports: [{atom, requirement | nil}], beamdash_req: String.t() | nil, shipped: [{atom, requirement | nil}]}} | {:error, msg}`.
  - It parses `mix.exs` with `Code.string_to_quoted`; the file is never evaluated.
  - It finds `def project`, whose keyword list literal must contain `app: atom`.
  - `deps:` is either a literal list, or a call to a local zero-arity function (`deps()`) defined as `defp deps do [...] end` or `def deps`, returning a literal list. Anything else (`++`, `if`, attributes, other calls) is refused: "deps must be a literal list in mix.exs".
  - Each dep is a literal `{name, req}`, `{name, opts}` or `{name, req, opts}`. It is split:
    - `:beamdash` goes to `beamdash_req`. A requirement, if present, must match `Beamdash.Plugin.version/0`; otherwise the error is `"needs beamdash <req>, this is <vsn>"`.
    - A name whose application is loaded in beamdash (`Application.spec(name, :vsn) != nil`) goes to `shipped`. A requirement, if present, must match that loaded version.
    - A dep with `runtime: false` (with or without `only:`) goes to `supports`. Its requirement is optional and must parse with `Version.parse_requirement/1` when present.
    - Anything else gives `"needs <name>, which beamdash doesn't ship"`.
  - If `supports` is empty: `"declare the application it supports as a runtime: false dependency in mix.exs"`.
  - Module attributes and other non-literal values inside a dep are refused, naming the dep.
- `Build.scan(src) :: {:ok, %{prefix: module, modules: [module]}} | {:error, msg}`.
  - Parse every `lib/**/*.ex` file. Collect the `defmodule` names: nested ones are joined to their parent with `Module.concat`, and `alias __MODULE__` forms are ignored.
  - All names must share one top-level prefix. That prefix must be a defined module, which is the entry.
  - No name may be loaded (`:code.is_loaded/1`) or available (`:code.which/1 != :non_existing`), except modules of **this same plugin app** when rebuilding: pass `allow: [modules]`.
  - `defimpl Proto, for: X`: `X` must be under the prefix.
- `Build.compile(src, ebin) :: {:ok, [module]} | {:error, msg}`.
  - Run `Kernel.ParallelCompiler.compile_to_path(files, ebin, return_diagnostics: true)` and format the errors as `file:line: message`.
  - On error, purge any modules that got loaded.
  - Elixir 1.15 returns `{:error, errors, warnings}` without diagnostics. Handle both shapes, or check `function_exported?`.
- `Build.check(modules, prefix) :: {:ok, plugin_map} | {:error, msg}`.
  - Exactly one module exports `__beamdash_plugin__/0`, and it is `prefix`.
  - All modules are under the prefix.
  - Every page module is among the compiled modules and exports `__live__/0`.
  - **Imports:** for each beam in ebin, read the `:imports` chunk with `:beam_lib.chunks`. Every imported module that isn't one of the plugin's own must be loaded or available on the code path. Otherwise return `{:error, "calls modules beamdash doesn't have: foo_mod, Bar. Call the attached node's modules with Beamdash.Plugin.rpc/4"}`.
- `Build.unload(modules)` runs `:code.purge` and `:code.delete` on each module, twice, to drop old code too.
- `Build.install_dir(app)` is `Path.join(plugins_dir(), to_string(app))`.
- `Build.plugins_dir()` is `Application.get_env(:beamdash, :plugins_dir)`, defaulting to `Path.join(:filename.basedir(:user_config, "beamdash"), "plugins")`.
- `Build.safe_rm_rf(path) :: :ok | {:error, msg}`.
  - It refuses unless the path's expanded, symlink-resolved form is strictly inside the expanded, symlink-resolved `plugins_dir()`.
  - Resolve symlinks by walking the path components with `File.read_link`, or use `:filelib.safe_relative_path`. Simplest: refuse if any component in the path under the plugins dir is a symlink (`File.lstat` type `:symlink`). Then compare expanded paths with `Path.relative_to` and check the result isn't absolute and doesn't start with `..`.
  - Never the plugins dir itself.

### Task 4: `Beamdash.Plugins` registry (GenServer)

**Files:**
- Create: `lib/beamdash/plugins.ex`
- Modify:
  - `lib/beamdash/application.ex`: add `Beamdash.Plugins` after `Beamdash.Logs`, plus a `Task.Supervisor` named `Beamdash.Plugins.TaskSup`, before it;
  - `test/test_helper.exs`: set `:plugins_dir` to a temp dir and clean it up after the suite, the same way it already does for the settings file.
- Test: `test/beamdash/plugins_test.exs` (`async: false`, named instances with a `dir:` option).

Spec sections: "Install", "Remove", "Rebuild", "Startup", "Active plugins and the menu".

**Consumes:** Tasks 1–3, `Beamdash.Target`, `Beamdash.Apps`.

**Interfaces (Produces):**
- `start_link(opts)` takes `name:`, `dir:` (default `Build.plugins_dir()`), `target:` and `refresh_ms:` (default 10_000).
- `list(server) :: [%{app, spec_text, source, resolved, supports: [{atom, req | nil}], status, plugin: map | nil, modules: [module]}]`.
  - `status` is `{:failed, msg}`, `:waiting`, `{:incompatible, app, running_vsn, req}` or `:active`. The last three are derived from the attached node's running applications, as in the spec's "Active plugins and the menu".
  - `Beamdash.Plugins.Compat.status(supports, running_apps) :: :active | :waiting | {:incompatible, app, vsn, req}` is pure, so it can be unit-tested.
    - Running vsns that aren't SemVer are padded: `"2.1"` becomes `"2.1.0"`, and `"2"` becomes `"2.0.0"`.
    - A vsn that still doesn't parse doesn't match, and the reason says it isn't a valid version.
    - A `nil` requirement matches any version.
    - With several supported apps, the plugin is `:active` if any of them matches. If none matches and some run, it is the first incompatible one.
- `active(server) :: [%{app, name, pages: [%{slug, label, module}]}]`, sorted by name.
- `page(server, app_string, slug) :: {:ok, %{app, plugin, page}} | {:error, :not_found | :waiting | {:incompatible, app, vsn, req}}`.
- `install(server, text) :: {:ok, ref}` returns immediately. Progress is sent to the caller as `{:beamdash_plugins, {:install, ref, step}}`, where `step` is `:checking | :fetching | :compiling | :loading`. The end is `{:beamdash_plugins, {:installed, ref, app}}` or `{:beamdash_plugins, {:install_failed, ref, msg}}`.
  - The work runs in a `Task.Supervisor.async_nolink` under `Beamdash.Plugins.TaskSup`. The GenServer only does the final bookkeeping, via a `handle_call(:commit, …)` from the task: it checks the app isn't installed again, writes `plugins.json` with tmp then rename, and records the plugin.
  - Only one install runs at a time. A second install gets `{:error, "another plugin is being installed"}`.
  - Temp dir: `Path.join(dir, ".tmp-#{System.unique_integer([:positive])}")`, deleted with `Build.safe_rm_rf` in all cases.
